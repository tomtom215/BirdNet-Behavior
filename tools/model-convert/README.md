# BirdNET V2.4 range-filter ("MData") models: TFLite to ONNX

Our Rust binary loads the species-occurrence ("range filter") model through ONNX
Runtime, but BirdNET ships it as TFLite. This directory converts the two TFLite
models that BirdNET-Pi ships into ONNX and measures how faithful the result is.

| file | what |
|---|---|
| `convert_mdata.py` | `convert` (TFLite to ONNX), `fingerprint` (name-agnostic graph hash), `report` (fidelity, week semantics, ISO vs 48-week) |
| `sensitivity_check.py` | breaks the ONNX on purpose to show that the comparison can fail |
| `requirements.txt` | exact versions used (`uv pip freeze`) |

The ONNX files are **not** committed (14 and 30 MB); they are regenerated by the
commands below. Where this run left them is in the last section.

Every claim below is labelled **VALIDATED** (a command was run and its output is
quoted or named here) or **CONJECTURED** (not tested, or inferred). Raw outputs of
the run (`report.txt`, `results.json`, CSVs, `sensitivity_*.txt`) are in
`$WORK/out/report/`.

## Regenerate

Python 3.12 (tf2onnx 1.17.0 documents 3.10 to 3.12; 3.13 was not tried). The venv
was put on tmpfs because the root disk had about 1 GB free; any path works.

```bash
uv venv --python 3.12 /dev/shm/mdata-venv
uv pip install -p /dev/shm/mdata-venv/bin/python \
    numpy onnx onnxruntime ai-edge-litert "tensorflow-cpu==2.19.1" "tf2onnx==1.17.0"
# VALIDATED: `uv pip install --dry-run -r requirements.txt` in a fresh venv resolves
# to the same 43 packages. CONJECTURED: the install from requirements.txt itself
# reproduces the results (the run used the unpinned command above, which resolved
# to exactly those versions).
. /dev/shm/mdata-venv/bin/activate
export TF_CPP_MIN_LOG_LEVEL=2

M=/path/to/BirdNET-Pi/model
python -I convert_mdata.py convert --tflite $M/BirdNET_GLOBAL_6K_V2.4_MData_Model_FP16.tflite    --onnx out/BirdNET_MData_V1.onnx --opset 17
python -I convert_mdata.py convert --tflite $M/BirdNET_GLOBAL_6K_V2.4_MData_Model_V2_FP16.tflite --onnx out/BirdNET_MData_V2.onnx --opset 17
python -I convert_mdata.py fingerprint --onnx out/BirdNET_MData_V1.onnx out/BirdNET_MData_V2.onnx

python -I convert_mdata.py report --labels labels.txt \
    --v1-tflite $M/BirdNET_GLOBAL_6K_V2.4_MData_Model_FP16.tflite    --v1-onnx out/BirdNET_MData_V1.onnx \
    --v2-tflite $M/BirdNET_GLOBAL_6K_V2.4_MData_Model_V2_FP16.tflite --v2-onnx out/BirdNET_MData_V2.onnx \
    --extra-onnx birdnetgo=/path/to/birdnet-go/internal/classifier/data/BirdNET_MData_V2.onnx \
    --out-dir out/report
python -I sensitivity_check.py --tflite $M/BirdNET_GLOBAL_6K_V2.4_MData_Model_FP16.tflite --onnx out/BirdNET_MData_V1.onnx --mutant-dir /dev/shm/mutants
```

`report` takes about 25 s, is single-threaded and deterministic (fixed grid, no RNG).
Only `convert` needs TensorFlow.

Versions used (VALIDATED, `results.json["versions"]`): Python 3.12.3, numpy 2.1.3,
onnx 1.22.0, onnxruntime 1.31.0, ai-edge-litert 2.3.0, tensorflow-cpu 2.19.1,
tf2onnx 1.17.0. tf2onnx 1.17.0's own README says it is tested against TF 2.13 to
2.15; TF 2.19.1 is outside that, and it worked here only in the sense that the
output passed the checks below.

## What the conversion produced

| | v1 | v2 |
|---|---|---|
| input | `MNET_INPUT`, float32 `[unk__107, 3]` | `serving_default_MNET_INPUT:0`, float32 `[unk__104, 3]` |
| output | `Identity`, float32 `[unk__108, 6522]` (single output) | `StatefulPartitionedCall:0`, float32 `[unk__105, 6522]` (single output) |
| batch dimension | **dynamic** (the TFLite `shape_signature` was `[-1,3]`; a `[1,3]` input runs as is, and N=1 is what the app uses) | **dynamic** |
| opset / IR | 17 / 8 (+ unused `ai.onnx.ml` 2) | 17 / 8 |
| ops | 62 nodes: MatMul 4, Relu 3, Sin 3, Min/Max/Exp/Div (v1 output activation) | 57 nodes: MatMul 4, Relu 3, Sin 3, Sigmoid |
| weights | float32 (9 of 9 large initializers are exactly representable in fp16, i.e. the FP16 weights were widened losslessly) | same, 9 of 9 |
| `onnx.checker.check_model` | passes | passes |

VALIDATED (`convert` output, `onnx.load`, an `astype(float16)` round-trip check).
Input/output *names differ between v1 and v2*; bind by index, not by name.
Nothing was stripped or renamed. The ONNX is about twice the TFLite size because the
weights are stored as float32.

Dynamic batch: VALIDATED that a 12-row batch through ONNX Runtime is bit-identical
(max abs 0.0) to twelve single-row calls for both models (`results.json["batch_check"]`).

**The files are not byte-reproducible.** VALIDATED: three conversions of the same
TFLite gave three different sha256 (v1 `477305d0...`, `49d4139d...`, `39bc29a7...` with sizes
14125683, 14125706, 14125833; v2 `40e807e7...`, `8f5c566d...`, `a2c4eca5...`) because tf2onnx's generated constant names change. The
`fingerprint` subcommand hashes the graph with names replaced by position, constants by
content, plus opsets and I/O signature; it was identical across all three runs
(v1 `e5fedba8b682140d...`, v2 `512bb10c1091c917...`; one of the three runs used
`python -m tf2onnx.convert --tflite ... --opset 17` directly instead of the script). Compare fingerprints, not file hashes.

Graph semantics (read from an `onnx` node dump, supplementary; the probes in step 4
confirm it empirically): the three inputs are turned into three 48-wide sine features
and concatenated (144) before four dense layers. The week feature is multiplied by
`(week > 0) AND (week < 49)`, so any week outside the open interval (0, 49) zeroes the
seasonal input. Lat and lon are not clamped. v1's output is `1/(1+exp(-0.5*clip(x,-15,15)))`,
v2's is a plain sigmoid.

Reading, in order of confidence:

- VALIDATED: conversion does **change** the outputs, by at most 3.7e-06 (v1) and 3.6e-06
  (v2) absolute (mean 3.5e-09 and 2.5e-08). It is not bit-exact.
- VALIDATED: that is the same size as TFLite's own kernel-to-kernel variation (XNNPACK vs
  reference kernels: 3.1e-06 and 4.5e-06), so the conversion adds nothing measurable beyond it.
- VALIDATED: 0 threshold crossings and 0 count differences at T=0.01 and 0.03 over all
  1344 calls, for both models.
- VALIDATED: birdnet-go's v2 ONNX is faithful on this grid, and its outputs are
  **bit-identical** to ours on all 8.77 M cells (max abs 0.0) even though the graphs
  differ: its `SELECT_V2` is a `Where`, ours is `Cast`/`Mul`/`Add` with constants 1.0 and 0.0;
  the fingerprints differ (`6586d763...` vs `512bb10c...`) while the 26 initializers hold the
  same arrays. How birdnet-go produced theirs (which tf2onnx input path) is not known.
- Exposure, VALIDATED: of the 8.77 M cells, 11 (v1) and 12 (v2) lay within the observed max
  error of T=0.03 (28 and 15 for T=0.01); none flipped. The closest TFLite value to a
  threshold was 4.4e-08 (v2, T=0.01); at T=0.03 it was 2.2e-07 (v1) and 2.0e-07 (v2).
- **CONJECTURED:** a species whose probability sits within about 4e-06 of the threshold can
  flip between TFLite and ONNX for some input not in this grid. The same applies between two
  TFLite kernels. Such a flip changes one borderline species in a list, not the list.
- VALIDATED that this comparison can fail (`sensitivity_check.py`, v1 / v2): week bound 49 to 50
  gives max abs 0.89 / 0.96 at week 49 and 1983 / 2732 crossing cells at T=0.03; a +1e-3 shift of
  the output bias (before the sigmoid) gives 11 / 56 crossing cells at T=0.03; +1e-4 gives 1 / 3;
  **+1e-5 and +1e-6 give 0 crossings and a max abs of 3.8e-06 to 5.9e-06, which is the noise floor.** So errors under about 1e-5 in the output logit are
  invisible to this test.

## Step 5: BirdNET-Pi's ISO week vs the 48-week scheme

## Limits (honest)

- The grid has 96 locations and 8 in-range weeks; all of step 4 and 5 is one location.
- Numerics checked only with the Python wheels of onnxruntime 1.31.0 on x86_64, CPU provider,
  default graph optimisation, 1 thread. **Not tested:** the Rust `ort` crate and the ONNX
  Runtime it bundles, aarch64 (Raspberry Pi) kernels, other optimisation levels. **CONJECTURED**
  that they agree to the same ~1e-6; opset 17 / IR 8 is the same as birdnet-go's file.
- Errors below about 1e-5 in the output are not detectable by this test (see the +1e-5 mutant).
- Label order equals output order is assumed, not tested.
- tf2onnx 1.17.0 was run with TF 2.19.1, outside its documented test matrix.
- Byte-for-byte reproducibility is not available; use `fingerprint`.
- The venv lives on tmpfs and disappears on restart; the requirements file recreates it.
