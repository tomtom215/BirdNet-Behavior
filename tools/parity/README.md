# Detection-parity reference: BirdNET-Pi side

Mechanically generated golden output from **BirdNET-Pi's own, unmodified code**
(`scripts/utils/{analysis,models,helpers,classes}.py`, commit
`88985a3a6fb1931a33f26ba1c46717a2a444c5b7`) running the real V2.4 FP16 TFLite
model, so that another implementation can be diffed against it.  Nothing in
here touches the Rust code.  Everything is regenerated by one script and the
output is byte-identical between two full runs (checked: the 41 matrix JSONs,
`species_list_e.json`, `onnx_vs_tflite.json`, `variants_compare.json`, sha256 of every `.npy`).

Labels used below: **VALIDATED** = I ran it and saw it; **CONJECTURED** = inferred, not run.

## Regenerate

```
git clone https://github.com/Nachtzuster/BirdNET-Pi "$PI" && git -C "$PI" checkout 88985a3a6fb1931a33f26ba1c46717a2a444c5b7
PI_ROOT="$PI" WORK=/some/scratch/dir [CROSSCHECK=1] tools/parity/regenerate.sh
```

Needs `uv`, `ffmpeg`, `curl`, HTTPS to raw.githubusercontent.com, archive.org, huggingface.co.
Keep `WORK` outside the repo (it receives ~40 MB of `.npy`, a venv and 17 MB of audio).

Primary stack (`requirements-primary.txt`): CPython 3.12.3, numpy 2.5.4, librosa 1.0.0,
resampy 0.4.3, soundfile 0.14.0, soxr 1.1.0, **ai-edge-litert 2.3.0** (aliased as `tflite_runtime.interpreter`),
onnxruntime 1.31.0, onnx 1.23.2, tzlocal 5.4.4.  ffmpeg 6.1.1-3ubuntu5.
Cross-check stack (`requirements-crosscheck.txt`): CPython 3.11.17, numpy 1.26.4, librosa 0.11.0,
**tflite-runtime 2.14.0** (the real package; BirdNET-Pi itself ships 2.17.1 or 2.11.0 and that exact build was NOT run).

How BirdNET-Pi's code is driven (the only non-BirdNET-Pi code on the path):
the `tflite_runtime.interpreter` alias; settings loaded via BirdNET-Pi's own `helpers._load_settings(path, force_reload=True)`
from a generated `birdnet.conf`; `analysis.MODEL=None` when SENSITIVITY/SF_THRESH/DATA_MODEL_VERSION change;
`$HOME` -> temp dir so `~/BirdNET-Pi/{include,exclude,whitelist}_species_list.txt` are the real loader's input;
`$TZ=UTC`; call-through spies (they return the original result) on `librosa.load`, `readAudioData`,
`analyzeAudioData`, `filter_humans` and `model.predict`.  The ISO week is realised as a file name
`YYYY-MM-DD-birdnet-HH:MM:SS.wav` (symlink) in ISO year 2020 (53 weeks), so `ParseFileName.week` is BirdNET-Pi's own.

## Findings

Self-check (**VALIDATED**): under `tests/helpers.py::Settings.with_defaults()` (lat 50, lon 5, SF_THRESH **0.003**, week 8 from the file name
date 2024-02-24) the three Pica pica detections are `[0.912, 0.9316, 0.8857]` at t=3,12,21 s, exactly equal (`==`, as in `analysis.py __main__`),
on both stacks.  It is not vacuous: SENSITIVITY 1.0 gives 0.9576/0.9702/0.9388.  Under `install_config.sh`'s literal 0.0/0.0 + SF_THRESH 0.03 the
result is **zero detections** (not a score mismatch: Pica pica is not in the 468-species list for 0.0/0.0).  With lat/lon 50/5 and 0.03 (or London) the same three values appear.
(`__main__` names `2024-02-24-birdnet-16:19:37.wav`, which is not in the clone; the unit test symlinks it.)

Pipeline facts (**VALIDATED** by running, unless marked):
* Input: `librosa.load(sr=48000, mono=True, res_type='kaiser_fast')` = `soundfile` float32 read, channel mean in float32 (bit-equal to `y.mean(axis=1)`),
  then `resampy.resample(..., filter='kaiser_fast')` (bit-equal for 44.1 k and 22.05 k; filter: 12289-tap half window, precision 512, rolloff 0.868) only if rate != 48000. 32-bit PCM comes out of libsndfile as float32 in [-1, 1) (bit-equal to `sf.read(dtype='float32')`).
* `kaiser_fast` needs `resampy`, which librosa 0.11/1.0 list only under the `tests` extra and BirdNET-Pi's `requirements.txt` omits: with resampy absent, 48 kHz files work and any other rate raises `ModuleNotFoundError`.  BirdNET-Pi's recorders always write 48 kHz.  CONJECTURED: that is why this has gone unnoticed.
* `splitSignal`: tail >= 1.5 s kept and zero-padded (7.6 s -> 3 chunks, 7.5 s -> 3, 7.4 s -> 2, 1.2 s -> 0).  Overlap 1.0 on 30 s -> 15 chunks, 2.0 -> 29; the last slot can run past the file end (`28.0;31.0`).
* SENSITIVITY s -> sigmoid slope `max(0.5, min(1-(s-1), 1.5))`: 1.25->0.75, 1.0->1.0, 0.75->1.25, 1.5->0.5.
* `run_analysis` only looks at each chunk's top 10 (`filter_humans` truncates), `score >= CONFIDENCE` on float32 scores.  Under numpy 2 that compare is float32 (`np.float32(0.7) >= 0.7` is True), under numpy 1.26 float64 (False); no clip hit the difference.
* **Weeks**: BirdNET-Pi passes the raw ISO week (1-53) to the MData model.  Any week outside 1-48 (-1, 0, 49-60 tested) gives one identical list per location and version, larger than any in-range week's (London v1: 101-122 species over weeks 1-48 vs 202 for 49-53; v2: 128-154 vs 258; Ithaca v1: 51-125 vs 199).  So ISO weeks 49-53 get a year-round list; do not clamp or wrap to 48.
* **lat/lon = -1/-1 is not "unset"** for V2.4: it is passed raw, i.e. a point in the Gulf of Guinea (list: Bias musicus, Accipiter melanoleucus, ... 462-472 species v1, 420-429 v2), and drops every temperate-zone detection in the fixtures.  0.0/0.0 is similar (468 at week 8).  The "unset" mask (`m[0] == -1`) exists only in `BirdNetV1._convert_metadata` (read from code, not run).
* Empty list means allow-all: SF_THRESH 1.01 -> 0 species -> Pica detected at 0/0.  SF_THRESH 0 -> all 6522 (`i_sf_*`).  Whitelist rescues a species from the occurrence filter only (`h_whitelist`); exclude beats whitelist and include (ran: Pica excluded when also whitelisted / included); a non-empty include list rejects everything not in it (ran).
* Default v1 / 0.03 drops Tawny Owl in London, Wales, Germany, Belgium (occurrence 0.007-0.022); it passes in Poland, France, Finland.
* Privacy filter is rank-based, not score-based: a chunk is "human" if any `Human*` label (`Human vocal/non-vocal/whistle`) is within the top `max(10, int(6000*PT/100))` labels, and its neighbours are masked too.  On the 47 chunks of the bird-only clips the best Human rank is 26-724; PT=1 (cutoff 60) masks 5/10 chunks of the Pica clip, PT=10 (cutoff 600) masks every chunk of every clip.  The LibriVox speech clip is fully masked at PT=0 with "Human vocal" scored only 0.017-0.041 (ranks 3, 14, 9, 2; chunk 2 is masked as a neighbour).
* Cross-runtime: the two stacks gave bit-identical 48 kHz chunks (including resampled and stereo clips), TFLite logits within 9.4e-5, and identical detections and MData lists in all 509 runs (`cross_runtime.json`).

ONNX vs TFLite (birdnet-go `BirdNET_v2.4_fp32_dfttrunc.onnx`, sha256 `3b72e88b...`, onnxruntime 1.31.0, batch 1; `golden/onnx_vs_tflite.json`):
54 chunks overall: logit max-abs **6.34**, mean-abs **0.090**, top-1 agrees on **53/54**, 1 of 13 threshold-crossing (chunk,label) pairs disagrees.
Not uniform: 41 ordinary chunks (9 clips; no zero padding, no digital silence, not 22.05 kHz-sourced) max-abs 0.153, mean 0.0128, top-1 41/41, score diff <= 0.0037.
Zero-padded tail chunks (7.5/7.6 s clips) max 1.49/1.34 (mean 0.41/0.36 on that chunk); the 22.05 kHz clip max 1.19, mean 0.39, and it is the one threshold disagreement;
digital silence max 6.34, top-1 differs (`Haliastur indus` vs `Engine`).  Cause of the large gaps: see the next section (VALIDATED).  Labels are identical and in the same order.
Scale for tolerances: perturbing the TFLite input by +-0.5 LSB (1/65536 FS) moves its own logits by a per-clip mean of 0.016-0.26 (22.05 kHz clip 1.80, synthetic 1.06; worst real chunk 4.6; two threshold flips among 12 pairs)
on these quiet recordings (the `ij_*` chunks have RMS 4-7e-4), whereas a 6e-8 relative perturbation moves them <= 3.2e-4.  Comparing logits to better than ~0.1 needs bit-exact input chunks.

Results (**VALIDATED** unless marked):
* **c and d are the same model for our purposes**: max |logit diff| 1.7e-5 over all 54 chunks including silence.  The truncation only shrinks the DFT matrices (2048x128 and 1024x320 instead of 2048x1025 and 1024x513) and adds four pad/zero initialisers; the rest of the graph is identical.
* **Ordinary chunks**: every build is within max 0.19 logit / mean 0.010-0.024 of the FP16 TFLite; max score diff a-b 0.0032, b-c 0.0033, a-c 0.0037, a-e 0.0073; no threshold crossing for a-b, b-c, a-c.  int8 (e) doubles the mean gap (0.024) and adds a 0.5 crossing.
* **FP16 weights vs conversion**, ordinary chunks, mean |diff|: FP16 vs FP32 weights in TFLite (a-b) 0.0098, the same rounding applied to the ONNX (d vs `r_all`, a copy of d with every float initialiser except the DFT matrices passed through float16) 0.0095; conversion alone at FP32 (b-d) 0.0071, at FP16 (a vs `r_all`) 0.0069; combined a-d 0.0121 = sqrt(0.0098^2 + 0.0071^2).  So the two sources are comparable and add in quadrature, about two thirds of the squared gap from FP16 weights (the split is CONJECTURED from that fit).
* **Digital silence and zero-padded tails: no build matches Pi.**  On the silence chunk the top-1 is `Haliastur indus` for a and `Engine` for b, c, d; max |diff| a-b 7.05, a-c 6.34, b-c 2.48.
* **Mechanism**.  The first graph ops min-max normalise every 3 s chunk, `((x - min) / (max - min + 1e-6) - 0.5) * 2`, so exact zeros (silence, padding) become one constant (zeros and a constant 0.1 give identical logits in every build).  Each STFT frame is then `constant * Hann`, whose non-DC spectrum is rounding noise, and the model's power-law compression (exponents 0.2295 / 0.1905) amplifies it.  Max over frames of `|Re X[k>=2]| / |Re X[0]|` for the all-zero chunk, read from inside each model: float64 FFT 1.8e-8; FP32 TFLite (real FFT) 1.8e-8; **FP16 TFLite 1.9e-5** (its Hann window is stored as float16, max change 2.4e-4); **ONNX 2.2e-5**: its stored DFT matrix is not the exact cosine matrix (entries off by up to 6.2e-4 / mean 3.8e-5 for the 2048-point one, 3.1e-4 for the 1024-point one, against 3e-8 for float32 rounding); a float64 matmul with the stored matrix still leaks 2.2e-5, with the exact matrix 1.8e-8.  CONJECTURED: the matrix was generated with float32 angles (my float32-angle recipe did not reproduce it exactly).  The two leaks have different causes and different patterns, hence the disagreement.
* **Controls**: replacing the zero tail of a padded chunk by +-1 LSB dither or by noise (sigma 1e-3) collapses every gap to 0.02-0.04; replacing it by a constant (3 LSB) leaves it at 1.47-1.64 (a-c) - the trigger is constancy, not exact zero.  Rounding only the two Hann windows of the ONNX through float16 moves silence a-c from 6.34 to 2.42 (top-1 becomes `Haliastur indus`, as in a) and the tail chunk from 1.49 to 0.46; rounding only the scalars (eps, exponents), only the mel matrices, or only the CNN weights changes nothing there.  The remainder is of the size of the FP32 conversion gap (b-c on the same chunks: 2.48 / 0.70), i.e. the ONNX DFT matrix.
* **Real part only**: the TFLite graph runs `RFFT2D` then `CAST complex64 -> float32`, i.e. the real part; its tensor equals `Re(FFT)` (max diff 7.6e-6 on a scale of 202) and not `Im`.  The ONNX uses a real cosine matrix, then mel matmul, square, power.  Both models: frames 2048/hop 278 and 1024/hop 280, 96 mel bins each (read from the graph); `dfttrunc` keeps DFT bins 0-127 (< 3 kHz) and 0-319 (< 15 kHz) of the two branches, byte-identical to the full matrices' columns, because the mel weights beyond are zero.
