05 · build order & the protect list

Sequencing

  1. Wave A — nav manifest. Rewrite nav.rs PRIMARY/MORE to the 6-home spine; add redirects; update parity tests. All six surfaces regenerate. Ships visibly with zero new pages.
  2. Wave B — Today merge + Station regroup. The two structural changes: fold dashboard+today into one home; regroup admin/nav.rs into the 6 task groups (admin shell already proves the shared-shell pattern). Highest impact.
  3. Wave C — Patterns / Reports / Recordings / Species tab shells. Each is a tabbed/view shell over existing partials — no renderer changes. Add the plain-English ledes + charts-then-disclosure.
  4. Wave D — the v3 backlog (from AUDIT_v3): aria-live + chart <title>/<desc>, export wizard UI, first-detection celebration, WS reconnect, axe/visual-regression CI, tokens doc, OpenAPI. Plus the docs-drift fixes (web-api.md still documents removed Basic-Auth).

don't touch — protect these

  • The nav manifest + parity tests — every new screen enters through nav.rs, never a hand-edited template.
  • CSP discipline — no inline styles (guard test), per-request nonce, no 'unsafe-inline'. Use data-style + classes, as the mocks do.
  • Server-rendered inline-SVG charts — no JS chart runtime, ever. Extend viz/, don't bypass it.
  • Honest liveness — flat idle baseline, never a fake waveform. The mocks keep this bar (Today signal, Recordings Live).
  • The OKLCH token set in app.css — the mocks add zero new tokens; close the remaining legacy .card bridges, don't extend them.
