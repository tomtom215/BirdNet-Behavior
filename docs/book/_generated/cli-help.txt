BirdNet-Behavior: Real-time acoustic bird classification with DuckDB behavioral analytics

Usage: birdnet-behavior [OPTIONS]

Options:
  -c, --config <CONFIG>
          Path to configuration file

          [env: BIRDNET_CONFIG=]
          [default: /etc/birdnet/birdnet.conf]

      --listen <LISTEN>
          Web server listen address. Defaults to all interfaces so the dashboard is reachable on the LAN out of the box; the `/admin` panel is gated by a password (set `CADDY_PWD`). Bind `127.0.0.1:8502` to restrict to this host

          [env: BIRDNET_LISTEN=]
          [default: 0.0.0.0:8502]

      --web-only
          Run only the web server (skip analysis daemon)

      --check-db
          Run database integrity check and exit

      --backup-db
          Create database backup and exit

      --doctor
          Run the preflight diagnostic and exit.

          Validates the configuration, audio source, model file, database integrity, disk space, and tool dependencies. Returns: - 0 — all checks passed - 1 — at least one warning (system will run, features degraded) - 2 — at least one error (system will not work until fixed)

          Run after install and any time the system behaves unexpectedly.

          [alias: --preflight]

      --doctor-json
          Run the preflight diagnostic and emit a single-line JSON document.

          Same checks and exit codes as `--doctor`, but the output is a machine-readable JSON object with `summary` and `checks` fields. Use for monitoring scripts (Nagios / Zabbix / Prometheus textfile collector / Home Assistant command sensor).

      --channel-report
          Report what a stereo microphone is actually delivering to the model.

          Records a few seconds from the configured ALSA device and prints, for the same audio: the level of each channel, the inter-channel delay (and the capsule spacing that implies), and what each way of reducing two channels to one would hand BirdNET.

          The model takes a single channel, so two must become one somewhere. Today that is a plain average, which is harmless for coincident capsules and a comb filter for spaced ones — at half a period of delay it cancels almost the entire signal. Whether a given station sits in that case depends on its microphone and cannot be answered anywhere but on the station.

          STOP THE SERVICE FIRST. An ALSA capture device is exclusive, so this cannot open a microphone the running station is already holding: `sudo systemctl stop birdnet-behavior`, run the report, start it again.

      --channel-report-secs <CHANNEL_REPORT_SECS>
          Seconds of audio to record for `--channel-report` (default 5).

          Longer is steadier. Run it while birds are actually singing: the cancellation is direction-dependent, so ambient noise alone can look benign on a microphone that loses badly on real song.

          [default: 5]

      --fix
          Attempt safe automatic repairs, then run the diagnostic.

          Implies `--doctor` (use with `--doctor-json` for machine-readable output). Repairs are idempotent and never destructive — currently they create any missing configured directories (the recordings/watch directory and the image-cache directory), the most common cause of "service runs but nothing is recorded" (e.g. after a tmpfs reset on reboot). The diagnostic then runs as usual and reflects the repaired state. Anything that needs root (ownership, packages) is reported, not changed.

      --model <MODEL>
          Path to the ONNX model file (overrides config)

          [env: BIRDNET_MODEL=]

      --labels <LABELS>
          Path to the species labels file (overrides config)

          [env: BIRDNET_LABELS=]

      --watch-dir <WATCH_DIR>
          Directory to watch for new audio files (overrides config)

          [env: BIRDNET_WATCH_DIR=]

      --process-existing
          Process audio files already present in watch directory on startup

      --analytics-db <ANALYTICS_DB>
          Path to the `DuckDB` analytics database file (enables behavioral analytics).

          When set, a file-backed `DuckDB` database is opened at this path for behavioral analytics queries.  The file is created if it doesn't exist.

          [env: BIRDNET_ANALYTICS_DB=]

      --refresh-extension
          Reinstall the behavioral `DuckDB` extension and exit.

          Force-downloads the latest `behavioral` build for the bundled `DuckDB` version from the community registry, loads it to verify, then exits. Requires `--analytics-db` (or `ANALYTICS_DB_PATH`) and network access.

      --verify-extension
          Verify the behavioral `DuckDB` extension actually loads, and exit.

          Opens a throwaway `DuckDB` database, loads the extension through the normal three-stage fallback, and reports the engine version, the extension version, and what the build-time embedded copy targets. Exits 0 when the extension loads and non-zero when it does not.

          It then runs the date-window query every dashboard opens with. That covers the other extension a station needs, `icu`, which is where `CURRENT_DATE` lives — and which DuckDB otherwise autoinstalls into `$HOME/.duckdb`, a path the shipped systemd unit mounts read-only.

          Unlike `--refresh-extension` this needs no network and writes nothing you care about, so it is the check to run on a station whose analytics pages are empty. Run it with networking disabled to prove the *offline* guarantee specifically: with no network neither the extension cache nor the community registry can satisfy either load, so only the embedded copies can.

      --offline
          Make no unsolicited outbound connections.

          Turns off every network call the station would otherwise make on its own: the daily update check against `api.github.com` and the Wikipedia species-image downloads. Integrations you configure explicitly — Apprise, `BirdWeather`, MQTT, SMTP, the heartbeat ping, the weather poll — are left alone, because asking for one is a decision the operator already made.

          For metered or cellular links, air-gapped deployments, and institutional review, where "which hosts does this contact?" needs one answer rather than a per-feature audit. See `docs/book/getting-started/configuration.md` for the full egress list.

          [env: BIRDNET_OFFLINE=]

      --no-update-check
          Skip the daily check for a new release.

          The station otherwise contacts `api.github.com` 60 seconds after start and every 24 hours after that, purely to log whether a newer version exists. It never installs anything on its own — updates are applied only from the admin panel. Implied by `--offline`.

          [env: BIRDNET_NO_UPDATE_CHECK=]

      --apprise-url <APPRISE_URL>
          Apprise notification server URL (e.g., `http://localhost:8000`)

          [env: BIRDNET_APPRISE_URL=]

      --notify-confidence <NOTIFY_CONFIDENCE>
          Minimum confidence threshold for Apprise notifications (0.0–1.0)

          [env: BIRDNET_NOTIFY_CONFIDENCE=]
          [default: 0.8]

      --deadman-hours <DEADMAN_HOURS>
          Hours of zero detections before the deadman watchdog raises an alert.

          The end-to-end "is the station actually detecting?" check: when no detection has been recorded for this many hours, a loud warning is logged and (if Apprise is configured) a notification is sent — once per quiet episode, with a recovery notice when detections resume. `0` disables alerting; the freshness gauge (`birdnet_detection_silence_seconds`) is exported regardless. Defaults to 24; config-file key: `DEADMAN_HOURS`.

          [env: BIRDNET_DEADMAN_HOURS=]

      --birdweather-token <BIRDWEATHER_TOKEN>
          `BirdWeather` station token for uploading detections

          [env: BIRDNET_BIRDWEATHER_TOKEN=]

      --latitude <LATITUDE>
          Station latitude for `BirdWeather` uploads

          [env: BIRDNET_LATITUDE=]

      --longitude <LONGITUDE>
          Station longitude for `BirdWeather` uploads

          [env: BIRDNET_LONGITUDE=]

      --image-cache-dir <IMAGE_CACHE_DIR>
          Directory for caching species images from Wikipedia.

          Defaults to an `images/` directory beside the database when unset, so a stock install shows species photos out of the box. Pass an empty value (`--image-cache-dir ""`) to disable image caching entirely — no Wikipedia fetches, e.g. for air-gapped deployments.

          [env: BIRDNET_IMAGE_CACHE_DIR=]

      --alsa-device <ALSA_DEVICE>
          ALSA device for microphone capture (e.g., `plughw:1,0`).

          For a single microphone. Use `--alsa-devices` to capture from several local mics at once.

          [env: BIRDNET_ALSA_DEVICE=]

      --alsa-devices <ALSA_DEVICES>
          ALSA devices for multi-microphone capture (semicolon-separated, or repeat the flag).

          Each device gets its own independent capture pipeline with filenames prefixed `MIC_1-`, `MIC_2-`, etc. (and matching per-source health metrics). Overrides `--alsa-device` when set. A semicolon — not a comma — separates devices because ALSA names themselves contain commas (e.g. `plughw:1,0`). Config-file equivalent: `ALSA_CARDS` (semicolon-separated); `ALSA_CARD` remains the single-mic key.

          [env: BIRDNET_ALSA_DEVICES=]

      --pipewire-device <PIPEWIRE_DEVICE>
          PipeWire/PulseAudio source for microphone capture.

          Uses `ffmpeg -f pulse` which works with both native `PulseAudio` and `PipeWire` (via `pipewire-pulse`). Leave empty or use `default` for the system default source. Takes precedence over `--alsa-device` when set. BirdNET-Pi equivalent: ALSA device pointing to a `PulseAudio` sink.

          [env: BIRDNET_PIPEWIRE_DEVICE=]

      --rtsp-url <RTSP_URL>
          RTSP URL for audio capture (e.g., `rtsp://camera.local:554/stream`).

          For a single stream. Use `--rtsp-urls` for multiple streams.

          [env: BIRDNET_RTSP_URL=]

      --rtsp-urls <RTSP_URLS>
          Comma-separated RTSP URLs for multi-stream capture.

          Each URL gets its own independent capture pipeline with filenames prefixed `RTSP_1-`, `RTSP_2-`, etc. Overrides `--rtsp-url` if set.

          [env: BIRDNET_RTSP_URLS=]

      --segment-duration <SEGMENT_DURATION>
          Duration of each recording segment in seconds (default: 15)

          [env: BIRDNET_SEGMENT_DURATION=]
          [default: 15]

      --recording-schedule <RECORDING_SCHEDULE>
          Recording schedule mode: "all-day" (24/7), "solar" (sunrise-to-sunset), or "fixed:HH:MM-HH:MM" (e.g., "fixed:06:00-20:00")

          [env: BIRDNET_RECORDING_SCHEDULE=]
          [default: all-day]

      --night-inhibit
          Inhibit recording during night hours (requires --latitude and --longitude)

          [env: BIRDNET_NIGHT_INHIBIT=]

      --twilight-offset <TWILIGHT_OFFSET>
          Minutes offset from sunrise/sunset for twilight recording (default: 30).

          Applies to both ends of the day. Use `--pre-sunrise-offset` / `--post-sunset-offset` to set them independently; either one overrides this for its own end.

          [env: BIRDNET_TWILIGHT_OFFSET=]
          [default: 30]

      --pre-sunrise-offset <PRE_SUNRISE_OFFSET>
          Minutes *before* sunrise at which recording starts.

          Overrides `--twilight-offset` for the morning end only. Dawn and dusk activity are rarely symmetric — the dawn chorus starts well before first light while evening song tails off quickly — so a station usually wants a longer pre-sunrise window than post-sunset one. Unset falls back to `--twilight-offset`.

          [env: BIRDNET_PRE_SUNRISE_OFFSET=]

      --post-sunset-offset <POST_SUNSET_OFFSET>
          Minutes *after* sunset at which recording stops.

          Overrides `--twilight-offset` for the evening end only. Unset falls back to `--twilight-offset`.

          [env: BIRDNET_POST_SUNSET_OFFSET=]

      --heartbeat-url <HEARTBEAT_URL>
          Heartbeat URL to ping after each analysis cycle (e.g., uptime monitoring)

          [env: BIRDNET_HEARTBEAT_URL=]

      --notify-trigger <NOTIFY_TRIGGER>
          Notification trigger mode: "each", "new-species", "new-species-daily"

          [env: BIRDNET_NOTIFY_TRIGGER=]
          [default: each]

      --notify-species-exclude <NOTIFY_SPECIES_EXCLUDE>
          Species to exclude from notifications (comma-separated scientific names)

          [env: BIRDNET_NOTIFY_SPECIES_EXCLUDE=]

      --notify-species-only <NOTIFY_SPECIES_ONLY>
          Only notify for these species (comma-separated scientific names)

          [env: BIRDNET_NOTIFY_SPECIES_ONLY=]

      --notify-title-template <NOTIFY_TITLE_TEMPLATE>
          Custom notification title template (supports $comname, $sciname, $confidence, etc.)

          [env: BIRDNET_NOTIFY_TITLE_TEMPLATE=]

      --notify-body-template <NOTIFY_BODY_TEMPLATE>
          Custom notification body template (supports $comname, $sciname, $confidence, etc.)

          [env: BIRDNET_NOTIFY_BODY_TEMPLATE=]

      --metadata-model <METADATA_MODEL>
          Path to the metadata ONNX model for species occurrence filtering.

          When set, the metadata model predicts which species are likely present at the station's location and time of year, filtering out unlikely species.

          [env: BIRDNET_METADATA_MODEL=]

      --sf-thresh <SF_THRESH>
          Species frequency threshold for the metadata model filter (0.0-1.0).

          Species with occurrence probability below this threshold are filtered out. Lower values allow more species through; higher values are more restrictive.

          [env: BIRDNET_SF_THRESH=]
          [default: 0.03]

      --privacy-threshold <PRIVACY_THRESHOLD>
          Privacy filter threshold for human voice detection (0.0 = disabled).

          When enabled, audio chunks containing human voice are suppressed along with adjacent chunks. Typical values: 0.01-0.03.

          [env: BIRDNET_PRIVACY_THRESHOLD=]
          [default: 0.0]

      --overlap <OVERLAP>
          Analysis window overlap in seconds (0.0-2.9, default 0.0).

          Controls how much consecutive 3-second analysis windows overlap. Higher overlap increases sensitivity at the cost of more CPU time. BirdNET-Pi equivalent: OVERLAP config option.

          [env: BIRDNET_OVERLAP=]
          [default: 0.0]

      --site-name <SITE_NAME>
          Custom site name displayed in page titles and header.

          Replaces the default "BirdNet-Behavior" branding in the web UI.

          [env: BIRDNET_SITENAME=]

      --lang <LANG>
          Language code for species name translation (e.g., "de", "fr", "ja").

          When set, species common names are translated to the specified language using `BirdNET` label files. Default: "en" (English).

          [env: BIRDNET_LANG=]
          [default: en]

      --labels-dir <LABELS_DIR>
          Directory containing `BirdNET` language label files for i18n.

          Label files should be named like `labels_de.txt`, `labels_fr.txt`, etc.

          [env: BIRDNET_LABELS_DIR=]

      --info-site <INFO_SITE>
          eBird/AllAboutBirds species info links: "ebird", "allaboutbirds", or "none"

          [env: BIRDNET_INFO_SITE=]
          [default: ebird]

      --audio-format <AUDIO_FORMAT>
          Audio format for extracted detection clips: "wav", "mp3", "flac", or "ogg".

          Non-WAV formats require ffmpeg or sox to be installed. BirdNET-Pi equivalent: AUDIOFMT config option.

          [env: BIRDNET_AUDIO_FORMAT=]
          [default: wav]

      --max-files-per-species <MAX_FILES_PER_SPECIES>
          Maximum number of extracted recordings kept per species (0 = unlimited).

          When set, the oldest files beyond this limit are deleted automatically. `BirdNET-Pi` equivalent: `MAX_FILES_SPECIES` config option.

          [env: BIRDNET_MAX_FILES_PER_SPECIES=]
          [default: 0]

      --disk-exclude <DISK_EXCLUDE>
          Comma-separated paths to exclude from disk usage monitoring.

          Files under these paths are never auto-purged.

          [env: BIRDNET_DISK_EXCLUDE=]

      --clip-retention-days <CLIP_RETENTION_DAYS>
          Reclaim the audio of detections older than this many days (0 = keep audio forever, the default).

          The age-based half of retention, alongside `--max-files-per-species` and the disk-full purge. Locked clips are exempt, and the detection records themselves are always kept — counts, species lists, trends and exports are unaffected; only the audio is reclaimed.

          [env: BIRDNET_CLIP_RETENTION_DAYS=]
          [default: 0]

      --disk-purge-threshold <DISK_PURGE_THRESHOLD>
          Disk-usage percentage at which the oldest recordings start being purged.

          The safety net that keeps a 24/7 station from filling its card: once the data disk crosses this, the oldest clips are deleted first, and locked clips are never touched. `BirdNET-Pi` equivalent: `DISK_PURGE_THRESHOLD`.

          `0` leaves the resolution to the config file / admin settings, then the 95 % default — the flag is only "set" when given, so it never silently overrides a value chosen in the UI.

          [env: BIRDNET_DISK_PURGE_THRESHOLD=]
          [default: 0]

      --stream-retention-secs <STREAM_RETENTION_SECS>
          Seconds a raw capture segment is kept in the transient stream directory.

          Raw segments are read by the detector and never needed again; draining them is what keeps the RAM-backed stream dir from filling. Far longer than the pipeline needs, so an unprocessed segment is never removed. `0` = resolve from config / admin settings, then the 600 s default.

          [env: BIRDNET_STREAM_RETENTION_SECS=]
          [default: 0]

      --stream-max-mb <STREAM_MAX_MB>
          Hard ceiling in mebibytes on the transient stream directory.

          Backstop for many-stream or backed-up runs; the oldest segments drop first. `0` = resolve from config / admin settings, then the 512 MiB default.

          [env: BIRDNET_STREAM_MAX_MB=]
          [default: 0]

      --custom-image-dir <CUSTOM_IMAGE_DIR>
          Directory containing custom species images (checked before Wikipedia cache).

          Files should be named `{lowercase_sci_name_with_underscores}.jpg`, e.g. `turdus_merula.jpg`. `BirdNET-Pi` equivalent: `CUSTOM_IMAGE` directory.

          [env: BIRDNET_CUSTOM_IMAGE_DIR=]

      --apprise-config <APPRISE_CONFIG>
          Path to Apprise config file (alternative/addition to --apprise-url).

          When set, uses the `apprise` CLI tool with `-c <file>` for notifications. `BirdNET-Pi` equivalent: `APPRISE_CONFIG_FILE` config option.

          [env: BIRDNET_APPRISE_CONFIG=]

      --weekly-report-schedule <WEEKLY_REPORT_SCHEDULE>
          Weekly report notification schedule.

          Send a weekly summary via Apprise on a fixed weekday. Values: "monday", "tuesday", ..., "sunday", or "disabled". `BirdNET-Pi` equivalent: `weekly_report` cron job.

          [env: BIRDNET_WEEKLY_REPORT_SCHEDULE=]
          [default: monday]

      --freq-shift-hz <FREQ_SHIFT_HZ>
          Frequency shift applied to extracted audio clips in Hz (0 = disabled).

          Shifts the pitch of saved detection clips upward by the given number of Hz, making high-frequency bird calls accessible to people with high-frequency hearing loss. Requires ffmpeg or sox. Typical values: 1000–4000 Hz. `BirdNET-Pi` equivalent: `FREQ_SHIFT` + `FREQ_SHIFT_AMOUNT` config options.

          [env: BIRDNET_FREQ_SHIFT_HZ=]
          [default: 0]

      --mqtt-host <MQTT_HOST>
          MQTT broker hostname or IP address for `IoT` detection events.

          When set, each bird detection is published as a JSON payload to the configured broker.  Compatible with Home Assistant, Node-RED, Mosquitto, and any MQTT 3.1.1-compatible broker. Example: `--mqtt-host mqtt.local`

          [env: BIRDNET_MQTT_HOST=]

      --mqtt-port <MQTT_PORT>
          MQTT broker port (default: 1883; TLS: 8883)

          [env: BIRDNET_MQTT_PORT=]
          [default: 1883]

      --mqtt-client-id <MQTT_CLIENT_ID>
          MQTT client identifier published in CONNECT packets.

          Must be unique per active connection on the broker.

          [env: BIRDNET_MQTT_CLIENT_ID=]
          [default: birdnet-behavior]

      --mqtt-username <MQTT_USERNAME>
          MQTT broker username for authentication

          [env: BIRDNET_MQTT_USERNAME=]

      --mqtt-password <MQTT_PASSWORD>
          MQTT broker password for authentication

          [env: BIRDNET_MQTT_PASSWORD=]

      --mqtt-topic-prefix <MQTT_TOPIC_PREFIX>
          MQTT topic prefix for published messages (default: "birdnet").

          Detections are published to `{prefix}/detection/{species}`. Status heartbeat is published to `{prefix}/status`.

          [env: BIRDNET_MQTT_TOPIC_PREFIX=]
          [default: birdnet]

      --mqtt-retain
          Set the RETAIN flag on MQTT detection messages.

          When set, the broker stores the last detection per topic and delivers it immediately to new subscribers.  Useful for Home Assistant sensors.

          [env: BIRDNET_MQTT_RETAIN=]

      --mqtt-ha-discovery
          Publish Home Assistant MQTT auto-discovery messages at startup.

          When enabled, BirdNet-Behavior publishes MQTT discovery payloads to `homeassistant/<component>/<uid>/config` so Home Assistant automatically creates sensors without manual `configuration.yaml` entries.

          Requires `--mqtt-host` to be set.  Harmless if HA is not running.

          [env: BIRDNET_MQTT_HA_DISCOVERY=]
