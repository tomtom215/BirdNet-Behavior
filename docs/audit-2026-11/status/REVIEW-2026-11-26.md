### What the review got wrong, or overstated

- **F12**: "the file path still imposes downmix" — each source already has a Mono/Left/Right/"Both, averaged" pick
  applied at capture (`admin/audio.rs:1466`, `capture/process.rs:512`), and the cancellation is documented
  (`tee.rs:437`).
- **F09**: per-model answer windows are already stored (`process.rs:387`); what is missing is narrower.
- **F21**: the half-updated classifier/labels pair does not happen on the catalogue paths (each file is renamed only
  after hashing to its own pin; the model is placed before its labels). Only the directory syncs were missing.
- **F16**: the flip lasts until the capture supervisor's next tick (2 s by default) for a supervised source.
- **F17**: right for the live writer. The maintenance connections set no level and get the bundled SQLite's default, FULL by its build flags (read, not run).

A test fixture misled this session once and is worth knowing: `helpers::test_support::test_state()` wraps a raw
in-memory connection that never received the writer's PRAGMAs, so it reads `synchronous=FULL`. A test about the
writer's settings must open the database as a station does (`AppState::new`).

## Batch 2: the six observations, the decisions, and integration

The maintainer's second brief raised six observations against PR #313's first batch, as reading, not as runs,
and authorised decisions for F09, F11, F12, F13 and F17. Each observation was reproduced as a failing Rust test
before anything was changed.

| Observation | Verdict | Evidence (red test, then fix) |
|---|---|---|
| F15: the transaction commits when the answers insert fails | **confirmed** | `a_row_is_never_stored_without_its_answers`, with a trigger that refuses the answers insert (`RAISE(ABORT, 'database or disk is full')`): the row was stored without them. Fixed in `4f0a504`: the error propagates, the row rolls back, and the detection is offered again |
| F02: live detections the database refuses are lost | **confirmed** | `a_live_detection_the_database_refuses_is_kept_for_the_next_start`. Fixed in `4f0a504` (kept through the same queue) |
| F01: thresholds are frozen at shutdown, not at inference | **narrowed** | Live and kept detections were both decided when processed, so "at shutdown" was not the defect; what was missing was one computation of the bars, recorded with the detection. `4f0a504` computes them once and replays them; deciding at inference time is not implemented |
| F03: a quarantine row names a queue file deleted at settlement | **confirmed, and wider** | `a_quarantined_detection_keeps_its_audio_through_review_and_approval` (replayed and live). Live quarantine audio was never playable either: the row named a stream segment purged within minutes. `4f0a504`, `3439d6a` |
| F04/F17: queue acknowledgements are synced, SQLite NORMAL commits are not | **confirmed** | `a_settlement_is_acknowledged_only_once_durable`. `4f0a504`: acknowledged after `wal_checkpoint(FULL)` succeeds or under `synchronous=FULL` |
| Resource bounds of the queue | **implemented and tested** | 180 events over 3 sources hold one recording in memory at a time; over 2 GiB, or with less than 512 MiB free, detections are kept without audio; an unwritable batch keeps its detections; an unfinished batch is removed at the next start (`4f0a504`) |

Decisions as implemented: F11 bounded streaming ingestion (`--ingest-recordings`, the admission check, the
refused-recording directory); F13 `OCCURRENCE_WEEK` with BirdNET-Pi's per-file week the default; F12 channel
selection kept, cancellation diagnosed, one channel selectable, each-channel analysis built and not enabled;
F09 padding, per-classifier scales and per-classifier filter rules; F17 FULL under `STATION_PROFILE=research`.
The transactional outbox covers BirdWeather (`95d6d34`); the other notification channels are not outboxed.

Corrections found while integrating, each checked against the code:

- **F12's "one live channel of two gives 0.25".** The energy ratio implemented (mean energy over the mean of
  the channels' energies) gives 0.5 for one live channel of two; 0.25 is the ratio to the loudest channel. The
  stereo warning floor is 0.25.
- **A station-wide channel choice failed mono recordings.** The capture path writes one-channel files for a
  source set to Left, Right or Mono, and the first decoder refused any file without the asked channel. A
  one-channel file is now its own only channel (`ec1fecb`).
- **A per-classifier privacy rule turns the privacy filter on by itself**, and the clip cutter decided "own
  segment only" from the station's rule alone; it now folds the same rules in (`ec1fecb`).
- **Refused in place, a long recording would have been purged unanalysed**: the stream directory drains every
  file past its age limit. It is moved aside (`1f4a5d5`).
- **The read-time event layer** (`97c2ee8`): a strict min(3600 s, sum) upper bound on a site's listening is
  wrong for the fall-back hour (7200 s) and for a segment credited to the hour it starts in; the bound uses the
  hour's real length and never falls below the lower bound. Event days are UTC dates, and a relabel changes an
  event's id, because the row id includes the species.
- **The history calendar's ledger read is decoration**: on a failed read the new "off" marking is dropped and
  an off day looks like a quiet listened day, as it always had (`2229ce4`).
- **NaN noise scores.** With per-classifier evidence, one classifier's NaN noise score no longer hides another's
  bark; that is the one input whose verdict changed (`8aa6040`).

run in a container:
