verified with its `SHA256SUMS.txt`) raised findings F01–F22 and routed the 138 open or in-progress checklist rows to

### What the review got wrong, or overstated

- **F12**: "the file path still imposes downmix" — each source already has a Mono/Left/Right/"Both, averaged" pick
  applied at capture (`admin/audio.rs:1466`, `capture/process.rs:512`), and the cancellation is documented
  (`tee.rs:437`).
- **F09**: per-model answer windows are already stored (`process.rs:387`); what is missing is narrower.
- **F21**: the half-updated classifier/labels pair does not happen on the catalogue paths (each file is renamed only
  after hashing to its own pin; the model is placed before its labels). Only the directory syncs were missing.
- **F16**: the flip lasts until the capture supervisor's next tick (2 s by default) for a supervised source.
- **F17**: right for the live writer. The maintenance connections set no level and get the bundled SQLite's default, FULL by its build flags (read, not run).

A test fixture misled this session once and is worth knowing: `helpers::test_support::test_state()` wraps a raw
in-memory connection that never received the writer's PRAGMAs, so it reads `synchronous=FULL`. A test about the
writer's settings must open the database as a station does (`AppState::new`).

## Verification

All of this is this session's own run, in this container (x86_64 Linux, 4 cores, rustc 1.100.0 and the 1.99
toolchain for MSRV), unless it says otherwise.

- **Red before green.** Each gate named in a commit message was run against the old code and seen failing on its
  own assertion before the fix; where a gate needed the new API, a scratch copy without that part was run, or the
  new function was first written with the old behaviour. Two gates were also checked to discriminate: with the
  replay's default outcome set to "settled" only the refusal test fails, and with the already-stored check off only
  the idempotency test fails. Two drafts failed for fixture reasons (a raw in-memory state without the writer's
  PRAGMAs; an effort test without a registered source and without the ledger's tick) and were fixed before being
  trusted.
- **`scripts/preflight.sh --msrv` on `066557f`, nothing uncommitted: all 18 gates ok** (fmt, typos 1.52.0,
  cargo-machete, installer drift, cargo-deny, cargo-audit 0.22.2, OSV, clippy `-D warnings` at default, all and no
  default features, rustdoc `-D warnings`, both builds, CLI help, the manual's link check, licence notices, doc
  tests, `cargo check` on 1.99). The first run, on `d11737c`, failed typos and clippy on this branch's own code;
  `e07f523` fixed them.
- **Unit tests** on `e07f523`: `cargo test --workspace --all-features --lib --bins --no-fail-fast`, exit 0, 12
  `test result:` lines, 5,374 passed, 0 failed, 1 ignored.
- **Integration tests** on `e07f523`: every one of the 328 files, 16 at a time per package (the linked binaries
  removed after each batch to keep the disk), `~/.duckdb` absent: 1,671 passed, 3 failed, 3 ignored. The three
  failures were the repository's own source scans reading this branch's new code (the failed-read sweep, the
  async-runtime scan, the ingest-gate scan); `ecc8357` answered each, and those three files then passed (3, 6 and 1
  tests), with root `daemon::` at 309 passed. The suite was not rerun whole after `ecc8357`, which touched only
  `src/daemon/` and the sweep's data file.
- **End to end**: `tests/a_stop_keeps_the_detections_it_has_not_processed.rs` (the built binary stopped with a
  backlog, then started) passed after the queue rewrite.
- **CI config**: `python3 scripts/check-ci-config.py` with cargo-mutants 27.1.0 exits 0; run durations were not
  read (no token), so headroom and annotation drift are judged only in CI.
- **`--doctor`** on a minimal configuration, with and without `DB_SYNCHRONOUS=full`: the same report apart from the
  file name (20 passed, 6 warnings, 0 errors, exit 1 "ready with warnings": no models in this container).

Not run here: the browser gates (`a11y.yml`; no template or stylesheet changed, but the manual's pages are served
under `/help`), the Docker image, the systemd install and upgrade tests, real-model inference, the aarch64 build,
CodeQL, mutation testing and coverage. Those run only in CI or need what this container lacks. The documents were
read, not rendered.

## Needs hardware, recordings or people

None of these is claimed. Each is a validation-matrix row (packet `04_VALIDATION_MATRIX.md`) this session could not
run in a container:

- **V04** power interruption at each commit boundary, on SD and SSD: the spool, the model files and `DB_SYNCHRONOUS`.
- **V10–V12** several USB devices and RTSP streams, unplugging, reconnection.
- **V13** DST folds, NTP steps and unset clocks on a real station.
- **V24** load during long histories and exports on a Pi.
- **V26–V28** real-model parity on aarch64 against a labelled corpus, precision, recall and calibration per
  species, cohort and forecast validation: these need annotated recordings and a study design, and independent
  review by an ornithologist. Nothing here is a statement about accuracy.
- **V05/V06** speech recall of the privacy filter: needs consented speech recordings.
