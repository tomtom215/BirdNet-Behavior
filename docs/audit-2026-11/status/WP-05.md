Tier B: `5c0d772` and the doc comments in the commits above (the effort module, the recording-effort queries,

`openapi.json`).

Choices made, each argued in its commit:

- Effort is accumulated in memory and folded every five minutes, keeping the ledger's SD-card write rate;
  `recording_effort` keeps its shape and now means "audio analysed". It is credited to the hour the audio was
  recorded, so a backlog is credited to the morning it holds.
- RES-15's interval is the exact Garwood 95 % Poisson interval on the count over the hours; it assumes
  independent detections, which they are not, so it is a floor on the uncertainty (stated in the docs).
- RES-19 uses the first and last run of 3 detection days within 7, not percentiles, which shift with the
  length of a stay.
- RES-14 / UIC-03: a day is not listened below 60 s summed over sources (one constant, shared with
  `listening.rs`); "partial" is under half the median of the previous 30 listened days, because the scheduled
  window is not available to the time-series crate. A day before the ledger's first row counts as listened.
- UIR-08 calls a week "hard to compare" when listened days differ by more than a fifth of the days compared.
